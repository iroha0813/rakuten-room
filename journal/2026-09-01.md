# 作業記録 2026-09-01（5日目）

朝の候補生成が止まっていた。8/30と同じ症状（回線IPの変動によるRakuten API 403）。

## 症状

`local/logs/2026-09-01.log`（10:01実行分）を見ると、8/30と全く同じ
`403 CLIENT_IP_NOT_ALLOWED` で落ちていた。

```
現在のグローバルIP: 220.146.83.217
```

同じログ内に `daily_goods` のSSLハンドシェイク失敗（`SSLV3_ALERT_HANDSHAKE_FAILURE`）も
出ていたが、これは403の前段で起きた一時的な通信エラーで、根本原因ではなかった。
IP登録後の再実行で発生せず、単発ノイズと判断。

## 対応

Rakuten Developers（https://webservice.rakuten.co.jp/app/list）の
「ROOM投稿候補ジェネレーター」アプリで、許可IPに `220.146.83.217` を追加（ユーザー対応）。
その後 `scripts/run_daily.ps1` を再実行し、10:26に復旧を確認。

```
候補プール 269件（日用品60 / ガジェット90 / 食品119）→ 5件選定
コミット「候補生成 2026-09-01」を push
```

  対処するなら `config/settings.yaml` 側の変更ではなく、Rakuten Developers側の設定変更のみで完結する。
