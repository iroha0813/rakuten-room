## 調べて分かったこと（すべて実機・実測）

### 当初の想定が外れていた点

**「アフィリンクを設置する」工程は存在しない。**
ROOMは「コレ！」投稿した時点でアフィリエイトリンクを自動生成する。渡すべきは
楽天市場の商品URLだけ。むしろ `affiliateId` をAPIに渡すと `itemUrl` 自体が
`hb.afl.rakuten.co.jp` のリダイレクトURLに差し替わり、ROOMが商品を認識できなく
なる恐れがある。`settings.yaml` の `affiliate.use_affiliate_links: false` を維持すること。

**ROOMの投稿画面は直接開ける。**

```
https://room.rakuten.co.jp/mix?itemcode=<itemCode>
```

`itemcode` は楽天APIが返す `itemCode` をそのまま使える。楽天市場のページを経由せず
「コレ！して投稿する」画面へ飛べる。コメントの事前入力は不可（`&comment=` は効かない）。

**ふるさと納税は楽天市場のジャンルツリーに存在しない。**
ルートジャンル39件を全確認済み。別サービス扱いなのでキーワード検索で拾っている。

**楽天APIはAPIごとにホストが違う。**

| API | ホスト |
|---|---|
| 商品検索 | `openapi.rakuten.co.jp/ichibams/` |
| ランキング | `openapi.rakuten.co.jp/ichibaranking/` |
| ジャンル検索 | `openapi.rakuten.co.jp/ichibagt/` |

いずれも `applicationId` に加えて `accessKey` が必須。

### ROOMの表示仕様（文章設計の根拠）

フィードと商品プレビューを実際に見て確認した。

| 項目 | フィード | 商品プレビュー |
|---|---|---|
| 投稿者のコメント | ✅ **2〜3行（40〜60字）で切れる** | ✅ 3行で「続きを読む」 |
| 価格 | ❌ | ✅ **ROOMが自動表示（常に最新）** |
| レビュー数・評価 | ❌ | ❌ **どこにも出ない** |

→ **勝負は冒頭40〜60字で終わっている。** ハッシュタグは誰の目にも触れない。
→ 価格を本文に書くのは重複かつ陳腐化する。書かない。
→ レビュー数はROOMが出さないので書く価値はあるが、冒頭に置くと弱い。中盤へ。

### GitHub Actionsは使えない

```
403 CLIENT_IP_NOT_ALLOWED
```

楽天のアプリ登録は「許可されたIPアドレス」が必須で、Actionsのランナーは毎回異なる
Azure IPから実行されるため全リクエストが失敗する。実測済み
（[run 33058423746](https://github.com/iroha0813/rakuten-room/actions/runs/33058423746)）。
ワークフローのcronは無効化し、`workflow_dispatch` だけ残してある。

## 見つけて直した不具合

| 不具合 | 影響 | 対応 |
|---|---|---|
| `affiliateId` を無条件にAPIへ渡していた | 商品URLがアフィリURLに化け、ROOMが認識できない恐れ | 明示的オプトインに変更 |
| 警告の `print` が cp932 で落ちる | **API成功済みの生成文を捨てていた**（5件中4件消失） | 標準出力をUTF-8化＋取得時点で確定 |
| 「マラソン限定」が伏せ字パターンから漏れ | 期間不明のセールを本文に書いていた | `ANY_DEAL_PATTERN` に統合 |
| 実績検証が「第◯位」しか見ていない | 「楽天ランキング1位」がすり抜け | 「ランキング◯位」「受賞」「認定」を追加 |

### 投稿直前の目視で見つかった誤り（重要）

自動検証が「5/5合格」と判定した文章を手で確認したところ、**4件に誤りがあった**。

- 「9/1〜9/13のクーポン」を8/27に訴求していた（未開始）
- 「27日正午まで半額」を27日夕方に訴求しかけた（期限切れ）
- お買い物マラソン（当日9:59終了）のクーポンを夕方に訴求していた
- 「年間1位」と「上半期1位」（どちらも2024年）から「2年連続1位」を捏造
- 骨取り商品を「骨が小さいから」と書き換えていた
- 「訳あり品」であることに触れていなかった
- 「iFace」を「iPhace」と誤字

対応として、商品名のセール期間を解釈して**期間外・期間不明ならお得情報をモデルに
渡さない**ようにし、実績表現の裏づけ検証を追加した。実例はすべて
`tests/test_accuracy.py` に再現テスト化してある。

**教訓: 自動検証だけでは不十分。投稿前の目視確認は省略しないこと。**
特に誤字とニュアンスの誇張は機械で拾えない。

## 現在の設定と方針

| 項目 | 値 | 理由 |
|---|---|---|
| `daily_count` | 5 | 手作業5〜10分で回せる量 |
| ジャンル配分 | 日用品2 : ガジェット2 : 食品1 | |
| `max_chars` | 250 | ROOMの上限は500。冗長化を防ぐための線 |
| `allow_deal_info` | true | ROOMで最も反応が取れる訴求のため解禁 |
| 絶対額（1,980円） | **常に禁止** | 価格が違うのは条件が変わるより重い嘘になる |
| 絵文字 | 2〜8個必須 | 装飾なしの説明文はフィードで読み飛ばされる |
| LLM | claude-haiku-4-5 | 1日5件で月100円未満 |

### 文章の設計原則

1. **1行目が全て。** 50字以内、完結した一文、困りごとか使う場面から入る
2. 金額は書かない。クーポン等は期間が検証できるときだけ
3. レビュー数は中盤に1回だけ、根拠として
4. 使った体験を創作しない
5. 商品情報にない実績・仕様を作らない
6. 友達に教える調子で、絵文字2〜5個

## 既知の問題・注意点

### 自宅IPの変動（最大のリスク）

本日だけで `220.146.64.52` → `106.155.52.110` と変わった。**変わるたびに
[楽天の管理画面](https://webservice.rakuten.co.jp/app/list)でIPを登録し直さないと毎朝止まる。**

止まったときは `local/logs/YYYY-MM-DD.log` に現在のIPと手順が出る。無言では止まらない。

→ **長期的にはOracle Cloud無料枠などの固定IP環境へ移行予定。**
移行時にコード変更は不要。`scripts/run_daily.ps1` をcron用スクリプトに置き換え、
そのサーバーのIPを楽天に登録するだけ。

### その他

- **候補ページのチェックボックスはブラウザ内のメモ**。システムには届かない。
  重複防止は `data/posted.jsonl`（提示した＝投稿したとみなす）で別に動いている
- **スキップした商品も180日間出てこない**。戻すコマンドは未実装（必要になったら作る）
- PowerShellスクリプトは**UTF-8 BOM付き**で保存すること。BOMなしだとcp932として
  読まれて構文エラーになる

## 現実的な期待値

ROOMは未稼働からのスタート。**最初の1〜2ヶ月は収益ほぼゼロが正常。**
楽天アフィリエイトの料率は概ね2%で、5,000円の商品が売れて約100円。

このシステムの価値は即座に稼ぐことではなく、毎日の投稿を5分に圧縮して継続を
可能にし、売れ筋データを蓄積して選定精度を上げ続けること。`report.py` の分析が
効き始めるのは提示件数と成約件数が溜まる3ヶ月目以降。
